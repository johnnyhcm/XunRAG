## 1. 系统设计思想（必读）

> 为什么先讲设计思想？因为**本系统的一切配置都围绕一条主链路展开**——不理解链路，就不知道"改哪里、为什么改"。这一章是后续所有章节的地图。

### 1.1 核心业务闭环

```
政策治理 → 检索 → 生成 → 行动
```

| 环节 | 做什么 | 质量取决于 | 管理员在哪操作 |
|---|---|---|---|
| 政策治理 | 政策入库（格式/切片/密级/版本） | **切片质量** | 政策管理（第 5 章） |
| 检索 | 找到与问题最相关的政策条款 | **检索参数** | 问答配置·检索环节（第 8 章） |
| 生成 | 基于检索结果组织可信回答 | **提示词** | 问答配置·生成环节（第 8 章） |
| 行动 | 推流程链接/联系人/风险提示 | **业务路由数据** | 问答路由（第 9 章） |

**一句话**：治理决定"有没有好料"，检索决定"找得准不准"，生成决定"答得可信不可信"，路由决定"能不能闭环到行动"。四个环节环环相扣，**前一个环节的质量会直接放大/稀释后一个环节的效果**——这就是为什么本系统强调"先治理、再入库"。

### 1.2 双模式架构（理解两种模式的调优思路差异）

系统提供两种问答模式，**调优思路完全不同**，请务必理解：

| 维度 | 高效模式（默认） | 智能模式 |
|---|---|---|
| 编排方式 | **Workflow**：流程固定、步骤由代码控制 | **Agentic**：AI 自主规划、只受提示词约束 |
| 技术框架 | LangGraph.js | Pi SDK |
| 检索方式 | 向量 RAG（BM25 词法 + 向量语义 + 精排） | 全文词法检索（grep 风格） |
| 检索颗粒 | 切片（chunk） | 全文 / 切片 |
| 回答特点 | 快、稳、省 Token | 深、全、可多轮推理 |
| **调优手段** | **调参数**（检索参数、超时、Top-K） | **调提示词**（角色设定、工具描述） |

**高效模式内部流程**（管理员调整"检索环节"配置时，要知道它作用于哪个步骤）：

```
用户提问
  → [1 理解] 意图识别（LLM）：拆解多意图、判断缺信息、识别转人工
  → [2 检索] 并行检索：BM25 词法路 + 向量语义路 → RRF 融合 → rerank 精排
              → 适用性加权（适用范围规则）→ 语言加权 → 去重
  → [3 组织] 组装上下文（Top-K 个切片 + 用户属性）→ LLM 流式生成 → 引用标注
  → [4 回答后] 流程链接卡片 / 联系人卡片 / 风险提示
```

**智能模式内部流程**：
```
用户提问 → Agent 自主规划 → 调用 policy_grep 工具（按需多次检索）
  → 判断检索充分性 → 综合推理 → 流式回答（引用来源章节）
```

> **给管理员的选型建议**：日常高频、简单查询用高效模式（快、稳、成本低）；复杂跨条款、需要推理的问题用智能模式。两者可并存，员工手动切换。

### 1.3 双存储架构（知道数据存在哪）

| 存储 | 内容 | 位置 |
|---|---|---|
| SQLite（元数据） | 用户/政策库/文件/版本/切片/配置/对话记录 | `data/policybot.db` |
| Chroma（向量） | 政策切片向量 + BM25 索引 | `data/vector-db/` |

- 系统启动时自动做**索引一致性校验**（SQLite 生效版本 ↔ Chroma 向量比对，清理孤儿）——管理员一般无需手动干预
- ⚠️ **备份时两个存储必须一起备份**（第 12 章的 backup 脚本已处理）；手动清库时必须同时清两处

### 1.4 权限模型三层（分别管什么）

| 层 | 模型 | 管什么 | 在哪配置 |
|---|---|---|---|
| 功能权限 | RBAC 权限角色 | 谁能用管理功能（用户管理/配置/政策管理…） | 权限角色（6.2 节） |
| 数据权限 | ABAC 属性规则 | 谁能**看到**哪些政策（可见范围）、AI 优先采用哪些（适用范围） | 政策库/文件编辑（6.3/6.4 节） |
| 密级 | 密级档位+策略 | 按密级施加保护（水印/禁复制/AI 可检索/审计） | 安全设置（第 10 章） |

## 2. 部署架构与环境要求

### 2.1 进程与端口

| 进程 | 技术 | 默认端口 | 职责 |
|---|---|---|---|
| backend | Node.js (Express + TS) | 3000 | 业务调度（认证/政策/问答/配置/统计） |
| python | Python (FastAPI) | 8001 | 检索引擎（转换/向量化/检索/精排） |
| frontend | Vite (React dev server) | 5173 | 仅开发模式；生产模式由 NSSM 托管 |

### 2.2 数据目录

```
data/
├── policybot.db      # SQLite 主库
├── vector-db/        # Chroma 向量库
├── uploads/          # 政策原始文件存档
├── certs/            # HTTPS 证书
├── logs/             # 日志（chat/audit/app/alerts 四类）
├── backup/           # 自动备份
└── pi-sessions/      # 智能模式会话记忆
```

### 2.3 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 22 | 后端 |
| Python | ≥ 3.12 | 检索引擎 |
| pandoc | ≥ 3.0 | Word 转换（pypandoc 内置） |
| 显卡（可选） | 8GB 显存起 | 本地模型推理（实测 RTX 5070 8G 流畅跑 9B）；无卡用 CPU 或云端模式 |

**模型文件**（首次使用前下载，`python tools/download_models.py`）：
- `bge-m3` 向量模型 → `models/embedding/bge-m3/`
- `bge-reranker-v2-m3` 精排模型 → `models/reranker/bge-reranker-v2-m3/`
- 本地 LLM（可选）→ `models/llm/<名称>/`（GGUF 文件）

## 3. 安装部署

### 3.1 开发模式（快速验证，10 分钟）

```bash
npm install                      # 安装依赖
pip install -r requirements.txt  # Python 依赖

# 终端 1：检索引擎
python app/python/server.py      # 监听 8001

# 终端 2：后端 + 前端
npm run dev                      # 后端 3000 + 前端 5173
```

浏览器访问 **`https://localhost:5173`**（注意是 https；自签证书点「高级 → 继续前往」）。
登录：工号 `A001`，初始密码 `Pass1234`（首次登录强制改密）。

> ⚠️ **开发模式警告**：本模式用于快速验证——**无 NSSM 进程守护（进程挂了不会自动拉起）、无自动备份**。正式使用请按 3.2 节执行生产部署。

**验证是否部署成功**：登录后 → 政策管理页 → 新建一个政策库 → 上传一份政策 → 发布 → 回到首页提问该政策相关内容 → 应返回带引用的回答。

### 3.2 生产模式（Windows 服务化）

```bash
npm run build                                   # 编译产物
node scripts/gen-cert.mjs                       # 生成 HTTPS 证书（生产换正式证书）
powershell -ExecutionPolicy Bypass -File scripts\install-services.ps1      # 注册 NSSM 服务（需管理员）
powershell -ExecutionPolicy Bypass -File scripts\register-schedules.ps1    # 注册定时任务（探活/备份/监控）
```

**NSSM 服务**（崩溃自动重启 + 开机自启）：
- `policybot-backend`（端口 3000）
- `policybot-python`（端口 8001）

**生产环境必设环境变量**（详见附录）：
- `POLICYBOT_MASTER_KEY`（加密密钥，32 字节 hex）
- `POLICYBOT_INITIAL_PASSWORD`（覆盖默认初始密码）
- `HTTPS_ENABLED=1` + `HTTPS_CERT`/`HTTPS_KEY`（正式证书）
- `BIND_HOST=0.0.0.0`（需局域网访问时）

> ⚠️ **开发与生产的环境差异**（部署踩坑提醒）：生产用 `node dist/main.js` 运行，读取资源的路径基于项目根（非开发目录）；NSSM 服务以系统账户运行，密钥目录需通过 `POLICYBOT_SECRETS_DIR` 显式指向（默认在用户主目录 `~/.policybot-secrets/`）。

### 3.3 局域网访问

1. 防火墙放行：管理员运行 `scripts\firewall-open.bat`（开放 5173/3000/8001）
2. 客户端访问：`https://<服务器IP>:<端口>`
3. 生产建议：使用正式证书（避免每台客户端手动信任自签证书）；或在内网部署企业 CA。

## 4. 首次配置（8 步走）

> **为什么强调顺序**：每一步的产出是下一步的前提——先有模型才能验证问答；先有政策才能验证权限；先有用户才能验证可见性。**按序执行可避免返工**。

### 第 1 步：登录并修改密码

- 入口：浏览器打开系统 → 登录页
- 操作：工号 `A001` / 初始密码 `Pass1234` → 系统强制要求修改密码 → 设置新密码（≥8 位，含大小写字母+数字）
- 验证：用新密码重新登录成功

### 第 2 步：配置模型接入（不配模型，问答无法工作）

- 入口：顶部导航「系统配置」→ 左侧「模型接入」（或直接 `/console/config/model`）
- 操作二选一：
  - **云端模式**（推荐先跑通）：顶部选择「云端 API」→ 服务商选 `DeepSeek`（或其他）→ 粘贴 API Key → 点「刷新模型列表」→ 确认模型下拉出现 → 选模型（如 `deepseek-v4-flash`）
  - **本地模式**：顶部选「本地模型」→ 填模型文件路径（GGUF）→ 按显卡配置参数（见 7.3）→ 保存
- 验证：页面顶部 **AI 运行指示灯**应显示绿色（云端=服务商+模型+Key 已配置；本地=模型已加载）
- 常见问题：Key 粘贴后提示"未配置"——确认是否保存成功（服务商切换后旧 Key 不会复用，需重新填）；本地模式模型加载需 30-60 秒

### 第 3 步：创建政策库并上传政策

- 入口：顶部导航「政策管理」（/admin）
- 操作：
  1. 点「新建政策库」→ 填名称（必填）、说明 → **此时可先不配可见/适用范围**（第 6 步统一配）→ 创建
  2. 进入政策库 → 点「上传文件」→ 选择 Word（.docx）或 Markdown 文件
- 验证：文件出现在列表中，转换状态由"转换中"变为"预览"

### 第 4 步：切片确认与发布

- 入口：政策管理 → 该文件 → 「切片预览」
- 操作：
  1. **检查自动切片**：系统已按标题自动切成多段；逐段确认章节归属正确
  2. **调整切片**：拖拽切片边界/合并/拆分；将明显无关的段落（封面/目录/页眉页脚）标记为不入库
  3. 确认无误 → 点「发布」→ 设置生效日期（默认今天；未来日期=待生效）
- 验证：员工端「政策库」能看到该政策全文；回到首页提问 → 能检索到
- **为什么这一步重要**：切片是检索的最小单元——切片过碎导致上下文不完整、过粗导致命中不精准。**治理质量直接决定问答质量**（第 1 章链路）

### 第 5 步：创建用户

- 入口：顶部导航「系统配置」→ 左侧「用户管理」（/console/users）
- 操作二选一：
  - **单个创建**：点「新建用户」→ 填工号（必填）、姓名（必填）、邮箱、部门、地区、合同类型、层级、岗位 → 保存（初始密码 Pass1234，首登强制改密）
  - **CSV 批量导入**：下载模板 → 按列填（工号/姓名/邮箱/部门/地区/合同类型/层级/岗位/状态）→ 上传 → 查看导入报告（选项值不在字典的会置空并在报告中标出）
- 验证：列表出现新用户；用该用户登录正常
- **提示**：用户属性（部门/地区/合同类型）是第 6 步权限规则的数据源——**属性填得准，权限和个性化才准**

### 第 6 步：配置权限（核心步骤）

**6a. 配置权限角色（功能权限——谁能管理什么）**
- 入口：系统配置 → 「权限角色」（/console/groups）
- 操作：新建角色 → 勾选功能（政策管理/用户管理/配置管理/统计查看…）→ 勾选管理范围（管理的政策库）→ 添加成员（手动指定，或配置动态规则按属性自动匹配）
- 验证：用该角色的成员账号登录 → 只能看到授权的管理功能

**6b. 配置可见范围（数据权限——员工能看到什么）**
- 入口：政策管理 → 政策库 → 「编辑」→ 可见条件
- 操作：设置库级可见规则（如：部门=人力资源部 OR 地区=内地），规则支持 AND/OR 组合
- 验证：用普通员工账号登录 → 看不到无权政策（列表/搜索/URL 直连均不可达——"装不存在"）

**6c. 配置适用范围（AI 优先采用什么——可选但推荐）**
- 入口：同上，编辑政策库/文件 → 适用范围
- 说明：适用范围与可见范围不同（详见 6.4）——**同一份政策可被看到，但 AI 回答时不优先采用**（如美国分公司政策对中国 HR 可见，但回答中国员工休假问题时不会采用）
- 验证：用不同地区账号提问同一问题 → 回答引用的政策应不同

### 第 7 步：配置业务路由（可选）

- 入口：系统配置 → 「问答路由」（/console/config/routes）
- 操作：
  - 「主题分类」：确认/调整 6 个内置主题（假期/考勤/出差/报销/外派/其他）的名称、关键词、范围说明
  - 「流程字典」：添加流程（如 请假 → OA 申请链接 URL）
  - 「对接人路由」：为主题配置对接人（选用户，可指定地区）
- 验证：提问"我要请假" → 回答末尾出现流程链接卡片；回复"转人工" → 收到对接人卡片

### 第 8 步：整体验证

用员工账号逐项检查：
- [ ] 登录、首页建议问题、两种模式可选
- [ ] 提问能检索到本部门相关政策的回答，引用可点击跳转原文
- [ ] 提问无关内容 → 拒答（"未在政策库中找到相关内容"）
- [ ] 看不到无权限政策（含搜索）
- [ ] 回复"转人工" → 对接人卡片
- [ ] 阅读政策全文 → 有水印（默认开启）

## 5. 政策管理操作指南

> 入口：顶部导航「政策管理」（/admin）。本页是政策生命周期管理的主战场。

### 5.1 政策库管理

**新建政策库**
- 入口：政策管理页 → 「新建政策库」
- 字段说明：
  | 字段 | 说明 | 建议 |
  |---|---|---|
  | 名称 | 必填，如"考勤与休假制度" | 按业务主题命名，便于员工浏览 |
  | 说明 | 可选 | 一句话说明适用范围 |
  | 库可见条件 | 空=全员可见；设置后仅满足规则的用户可见 | 见 6.3 |
  | 库适用范围 | 空=全员适用；设置后 AI 优先采用适用政策 | 见 6.4 |

**政策库操作**：停用（库内全部文件不可检索/浏览）、编辑属性、删除（仅空库可删）。

### 5.2 上传与转换

- 支持格式：**Word（.docx）与 Markdown（.md）**——不支持 PDF（见 1.1 治理理念：找不到 Word 原稿说明治理未到位）
- 上传后系统自动：
  - Word → Markdown 转换（pandoc），图片自动提取
  - 语言检测、封面/目录/页眉页脚自动标记
  - 转换质量标记：`ok` 正常 / `need_review` 需人工检查（如文档无标题样式）
- **常见转换结果**：
  - 标题识别：内置标题样式 → 自动分级；无标题样式 → 启发式补标（"第X章/第X条/一、"等）；仍无标题 → 标记 need_review，需人工处理
  - 表格：简单表格转 Markdown 竖线表格；复杂表格（合并单元格）转"字段：值"文本；中英双语保留

### 5.3 切片（治理核心动作，务必人工确认）

| 操作 | 入口 | 说明 |
|---|---|---|
| 查看切片 | 文件 → 「切片预览」 | 直观看到每个切片内容与章节归属 |
| 调整切片 | 切片预览页 | 拖拽边界、合并/拆分；标记段落"不入库"（仅原文可见） |
| 标题处理 | 切片预览页 | 标题默认并入所属切片（保证标题词可检索）；手动切分可让标题独立成块 |

**切片质量判断标准**：一个切片应是一个完整的"条款/小节"——包含足够的上下文（条件+结论），又不过度冗余。

### 5.4 发布与版本管理

| 操作 | 说明 | 生效规则 |
|---|---|---|
| 发布 | 设置生效日期 | 未来日期 = 待生效（到期自动切换，无需人工操作） |
| 编辑版本 | 修改生效日期等 | 已发布版本锁定部分字段 |
| 废止版本 | 停止使用 | 废止后不再被 AI 检索、员工不可读 |
| 删除 | 草稿/未发布可删；已发布禁删 | 需先废止 |
| 停用政策库 | 库级开关 | 停用后库内全部文件统一不可检索/浏览 |

**版本生效判断**：同一政策线可有多版本，系统按生效日期判定"当前生效版本"——**AI 检索只参考当前版本，员工阅读也只显示当前版本**。发布新版会自动闭合旧版生效区间。

**所有操作留痕**（审计日志，见 11.2）。

### 5.5 密级设置

- 每篇政策**必须设置密级**（安全基线）
- 密级档位与保护策略在「安全设置」配置（第 10 章）
- 关键机制：密级为 `ai_searchable=false` 的政策——**人可读、AI 不引用**（防止 AI 泄露机密内容）

## 6. 用户与权限操作指南

### 6.1 用户管理

> 入口：系统配置 → 「用户管理」（/console/users）

**单个创建**：新建用户 → 工号（必填）+ 姓名（必填）+ 邮箱 + 各属性字段 → 保存。
**CSV 批量导入**：
1. 下载模板（列：工号/姓名/邮箱/部门/地区/合同类型/层级/岗位/状态）
2. 填写（注意选项值必须与「用户属性」字典中的选项一致，否则该列置空并报告）
3. 上传 → 查看导入报告（成功/跳过/置空明细）
4. 导入用户初始密码 `Pass1234` + 首登强制改密

**其他操作**：重置密码（重置为初始密码，线下告知）、停用/启用（停用立即失去全部访问权限）、编辑属性。

### 6.2 权限角色（RBAC——功能权限）

> 入口：系统配置 → 「权限角色」（/console/groups）

**角色 = 成员 + 功能 + 管理范围**（多角色取并集）：

| 维度 | 配置方式 | 说明 |
|---|---|---|
| 成员 | 手动指定 + 动态规则 | 动态规则按用户属性自动匹配（入转调离实时生效） |
| 功能 | 勾选 | 政策管理 / 用户管理 / 角色管理 / 配置管理 / 统计查看 / 知识库全局管理 |
| 管理范围 | 勾选政策库 | 指定可管理的库（或 ALL） |

**内置角色**：
- **系统管理员组**：全部功能 + 全部库（安全红线——仅手动添加成员，不参与动态规则）
- **员工组**：仅查询功能（全员默认）

**动态规则语法**（用于成员自动匹配）：
- 同规则组内的条件 = AND（同时满足）
- 不同规则组 = OR（任一满足）
- 操作符：`in`（包含）/ `not_in`（不包含）
- 示例：`地区 ∈ [北京, 上海] AND 部门 = 人力资源部` → 满足的成员自动入组

### 6.3 可见范围（ABAC——数据权限）

> **解决"谁能看到"**。双层结构：
> 政策库级可见条件（空 = 全员可见）→ 文件级可继承库或进一步收窄（**不可超出库级**）

- 配置位置：政策管理 → 编辑政策库/文件 → 可见条件
- 规则形式：`字段 ∈ 值` 组合（AND/OR）；字段来自用户属性（部门/地区/合同类型/层级/岗位…）
- **动态生效**：员工属性变化 → 可见性实时更新（无需重新登录）
- **防探测**：无权内容"装不存在"——列表不显示、搜索不命中、URL 直连 403

**示例配置**（考勤库）：
```
库级可见条件：部门=人力资源部 OR 合同类型=正式
  └─ 深圳考勤细则（文件级）：地区=深圳 AND 合同类型=正式   ← 在库级基础上收窄
```

### 6.4 适用范围（与可见范围的区别——易混淆概念）

| | 可见范围 | 适用范围 |
|---|---|---|
| 语义 | **谁能看** | **AI 回答时优先采用谁的** |
| 机制 | 硬过滤（不命中=看不到） | 软排序（不命中=降优先级，不隐藏） |
| 场景 | 数据安全边界 | 回答准确性 |

**示例**：中国 HR 有权限查看美国分公司政策（可见），但当她问"我休假能休几天"时，AI 不会优先采用美国政策（不适用）——而是优先采用适用她所在地区的政策。**适用范围配置建议**：跨地区/跨部门通用的政策，可配置适用范围让 AI 精准选材。

**配置位置**：政策管理 → 编辑政策库/文件 → 适用范围（规则形式与可见范围相同；文件级可继承库级）。

### 6.5 用户属性字段字典

> 入口：系统配置 → 「用户属性」（/console/config/fields）

管理用户可配置的属性字段（**权限规则和个性化回答的数据源**）：

| 配置项 | 说明 |
|---|---|
| 字段类型 | 单选 / 多选 / 文本 |
| 是否必填 | 新建/导入时校验 |
| 注入对话上下文 | 是否用于个性化回答（仅内置核心字段默认开启；预留字段默认关） |
| 选项维护 | 值/显示名分离（值稳定匹配，显示名可改/多语言） |

内置核心字段：部门、地区、合同类型、层级、岗位（不可停用/删除）。预留自定义字段 10 个（custom_1~10），可按企业需要启用。

## 7. 模型接入操作指南

> 入口：系统配置 → 「模型接入」（/console/config/model）
> 页面顶部有 **AI 运行指示灯**（10 秒轮询）：云端=服务商/模型/Key 状态；本地=模型/引擎/显存。

### 7.1 选择接入模式

| 模式 | 数据流向 | 适用场景 |
|---|---|---|
| 云端 API | 问题+政策内容发往外部大模型服务 | 追求效果、无严格数据出境限制 |
| 本地模型 | 全部推理在本机完成，**数据不出内网** | 金融/政务等合规要求严格 |

> 切换方式：页面顶部 Segmented 一键切换（即保存、立即生效）；切换不会清除已配置的 API Key。

### 7.2 云端 API 配置步骤

1. 模式选「云端 API」
2. 服务商：`DeepSeek`（推荐）/ `OpenAI` / `Anthropic` / `自定义`（OpenAI 兼容端点）
3. API Key：粘贴保存（**AES-256-GCM 加密存储**，明文不落库；各服务商独立保存，切换服务商不重填）
4. 模型：点「刷新模型列表」→ 下拉选择（如 `deepseek-v4-flash`）
5. 点「测试连接」验证
6. 验证：顶部指示灯变绿

**Key 安全机制**：Key 加密存于 `~/.policybot-secrets/llm.key.<provider>.enc`；加密密钥来自 `POLICYBOT_MASTER_KEY` 环境变量（生产必设）。**服务商变更且未填新 Key → 旧 Key 自动失效**（防误用旧 Key）。

### 7.3 本地模型配置步骤

1. 下载 GGUF 模型文件 → 放 `models/llm/<名称>/`
2. 模式选「本地模型」→ 填模型文件路径
3. 按显卡调整参数：

| 参数 | 默认 | 调整建议 |
|---|---|---|
| 上下文长度 | 16384 | 8GB 显存建议 ≤16K；显存大可加大 |
| KV cache 量化 | 开 | 省显存；大显存可关（略提精度） |
| GPU 层数 | 40 | -1=全量GPU / 0=CPU / N=前N层；Windows 下须显式指定 |
| 思考模式 | 关 | 本地 9B 思考成本高收益低，建议保持关 |
| 并发数 | 2 | 并发请求（超出排队）；人多可调高，注意显存 |
| 排队超时 | 60000ms | 排队超 60 秒取消 |

4. 保存 → 等待模型加载（30-60 秒，指示灯变绿）
5. 验证：提问 → 回答正常；`nvidia-smi` 可见显存占用

**性能参考**：RTX 5070 8G 跑 9B Q4 流畅；本地模型响应偏慢（每轮 2-5s），智能模式 agent 多轮工具调用首字可能 30-90s——**属正常，勿误判为卡死**。

### 7.4 模型推理开关（reasoning）

| 配置项 | 默认 | 效果 |
|---|---|---|
| 高效模式·模型推理 `efficient.reasoning` | 关 | 开=生成时思考更深（更慢更贵）；关=快而稳。**内部步骤（意图识别）不受影响** |
| 智能模式·模型推理 `smart.reasoning` | 开 | 开=深而全（默认）；关=降成本延迟 |

> 配置位置：问答配置 → 高效模式 Tab → 「组织回答」分区 / 智能模式 Tab → 「思考」分区。

## 8. 问答配置中心详解

> 入口：系统配置 → 「问答配置」（/console/config/params）
> **页面结构与通用操作**：
> - 顶部：AI 运行指示灯
> - 三个 Tab：**高效模式 / 智能模式 / 通用**（对应三大类配置）
> - 每个 Tab 内按分区 Card 组织（高效：1.理解问题 / 2.检索政策 / 3.组织回答 / 4.回答之后；智能：提示词 / 检索 / 思考；通用：首页欢迎区 / 体验文案 / 反馈 / 会话 / 工具 / 安全）
> - **操作方式**：本地编辑（改动的项蓝色高亮 + 未保存标记）→ 点分区 Card 右上角「保存改动（N）」→ **保存即生效，无需重启**
> - 每项可「恢复默认」；用户可见文案类（i18n 项）显示英文值编辑区（英文未填显示橙色提醒）

### 8.1 高效模式：理解环节（意图识别）

> 界面位置：高效模式 Tab → 「1. 理解问题」分区

| 配置项 | 默认 | 作用 | 调什么情况调 |
|---|---|---|---|
| 意图识别提示词 `efficient.intent.prompt` | 内置 | 告诉 AI 如何拆解用户问题（动作意图×业务主题）；`{topics}/{intent_types}/{processes}` 由数据字典动态注入 | **勿删占位符**；如企业术语特殊（如"工单"=报销），可在规则中补充 |
| 意图上限 `efficient.intent.max_intents` | 5 | 一次提问最多拆几个独立意图 | 问题通常 1-3 个意图即可；上限过高会引入噪音 |
| 意图识别超时 `efficient.intent.timeout_ms` | 20000ms | 意图识别调用超时 | 模型慢时可调大 |

**这段的作用**：决定"AI 是否理解对问题"——拆错意图 = 检索错方向。如果发现"AI 回答答非所问"，先检查这里。

### 8.2 高效模式：检索环节（决定"找得准不准"）

> 界面位置：高效模式 Tab → 「2. 检索政策」分区。**本分区参数直接影响检索质量与成本，是调优主战场。**

**检索策略开关**

| 配置项 | 默认 | 作用与影响 | 何时调整 |
|---|---|---|---|
| 混合检索 `efficient.retrieve.hybrid` | 开 | 开=BM25 词法+向量语义双路融合（召回更全）；关=纯向量 | 仅当纯向量已足够且想省算力时关；**词法路对精确词（条款号/专有名词）很重要，一般保持开** |
| rerank 精排 `efficient.retrieve.rerank` | 开 | 开=用 bge-reranker 对候选精排（精度提升明显，耗时 ~1s）；关=跳过（更快） | 追求速度且精度可接受时关；**质量优先场景保持开** |

**召回数量参数**（决定"给 AI 多少料"）

| 配置项 | 默认 | 作用与影响 | 何时调整 |
|---|---|---|---|
| Top-K `efficient.retrieve.top_k` | 5 | 最终进入生成的切片数 | **太小**=信息不足（回答不完整/易拒答）；**太大**=上下文过长（Token 成本↑、噪音↑）。回答不完整时加大 |
| fused 候选数 `efficient.retrieve.fused_candidates` | 20 | 融合后、精排前的候选数 | 一般不动；检索质量差时可加大（精排前多留点） |
| RRF 融合 k `efficient.retrieve.rrf_k` | 60 | 双路融合参数（越大两路越平均） | 一般不动 |

**词法检索参数**（BM25，一般无需调整）

| 配置项 | 默认 | 说明 |
|---|---|---|
| BM25 k1 `efficient.retrieve.bm25_k1` | 1.5 | 词频饱和参数 |
| BM25 b `efficient.retrieve.bm25_b` | 0.75 | 文档长度归一化参数 |

**适用性软排序权重**（结合第 6.4 节适用范围）

| 配置项 | 默认 | 作用与影响 | 何时调整 |
|---|---|---|---|
| 适用加分 α `efficient.retrieve.applicable_boost` | 0.3 | 命中适用范围规则的政策 → 分数 ×(1+α) | **希望 AI 更"懂你"（优先采用适用政策）→ 调大**；但过大可能挤掉真正相关的通用政策 |
| 不适用减分 β `efficient.retrieve.inapplicable_penalty` | 0.15 | 明确不适用 → ×(1-β) | 跨地区/跨部门政策多时，可调大让 AI 更聚焦 |

**超时参数**（防止单轮问答卡死）

| 配置项 | 默认 | 说明 |
|---|---|---|
| 请求超时 `efficient.request.timeout_ms` | 30000ms | 单轮问答整体超时 |
| 检索超时 `efficient.retrieve.timeout_ms` | 30000ms | 调 Python 检索超时 |
| 分支检索超时 `efficient.branch.timeout_ms` | 15000ms | 多意图单分支超时（超时降级空结果，不拖垮整体） |

**这段的调优逻辑**：检索效果不好时，先确认**混合检索/精排是否开启** → 再调 **Top-K** → 最后微调**适用性权重**。不要一上来就动 BM25 参数。

### 8.3 高效模式：生成环节（决定"答得可信不可信"）

> 界面位置：高效模式 Tab → 「3. 组织回答」分区

| 配置项 | 默认 | 作用与影响 | 何时调整 |
|---|---|---|---|
| 生成系统提示词 `efficient.generate.prompt` | 内置 | 生成回答的行为约束（分节/引用标注/拒答/防注入）；`{reject_text}/{profile_section}` 系统注入 | 企业风格要求（如回答须附政策编号）时补充；**防注入约束勿删** |
| 低置信信号词 `efficient.generate.low_confidence_words` | 未找到…\|无法确定… | 回答含这些词 → 判定低置信 | 企业常用表达不同时调整（\ 分隔） |
| 对话轮数上限 `efficient.generate.max_rounds` | 5 | 单会话问答轮数上限 | 员工多轮追问需求高时调大（注意资源） |
| 生成超时 `efficient.generate.timeout_ms` | 60000ms | 流式生成超时 | 模型慢时调大 |
| 模型推理 `efficient.reasoning` | 关 | 见 7.4 | 需要更深回答时开（更慢更贵） |

**防幻觉机制说明**（管理员应了解）：系统在**检索 0 命中时直接拒答**（不调用 LLM 生成）——这是代码级保障，不依赖提示词。所以"回答不完整"排查方向是**检索**（8.2），不是生成提示词。

### 8.4 高效模式：回答环节（对外文案）

> 界面位置：高效模式 Tab → 「4. 回答之后」分区。**全部为对员工展示的文案，可自定义**（支持中英双语维护）。

| 配置项 | 默认 | 出现场景 |
|---|---|---|
| 拒答文案 `efficient.reply.reject_text` | 未在政策库中找到相关内容。 | 检索无结果/无关问题 |
| 反问文案 `efficient.reply.clarify_text` | 为了给您更准确的答案，请补充： | 问题缺关键信息（如问出差补贴未说城市） |
| 转人工文案 `efficient.reply.contact_text` | 您的问题需要人工协助，为您联系以下同事： | 员工回复"转人工" |
| 主题引导文案 `efficient.reply.topic_guide_text` | 为了帮您找到合适的联系人，请说明… | 转人工但未识别业务主题 |
| 行动建议文案（流程入口） `efficient.reply.action_process_text` | 前往办理 | 流程入口卡片按钮 |
| 行动建议文案（查询弱提示） `efficient.reply.action_query_text` | 是否需要申请？ | 查询类回答末尾弱提示 |

**总开关**

| 配置项 | 默认 | 说明 |
|---|---|---|
| 高效模式开关 `efficient.mode.enabled` | 开 | 关闭后员工对话页不显示高效模式（只能用智能模式）；向量化照常，可随时重开 |

### 8.5 智能模式：提示词（决定 AI 的行为边界）

> 界面位置：智能模式 Tab → 「提示词」分区。**智能模式的调优主战场在提示词（而非参数）**。

| 配置项 | 默认作用 | 何时调整 |
|---|---|---|
| Agent 角色设定 `smart.prompt.system` | 回答风格与行为边界（仅依据检索结果、防注入、简洁结论优先） | 企业风格要求（正式/亲和）时改写 |
| 宽泛先澄清 `smart.prompt.clarify` | 问题只提主题（如"休假"）未指明细节 → 先反问澄清，不一次性列举 | 保持默认；如发现 AI 回答过于啰嗦可强化 |
| 流程字典注入 `smart.prompt.process_dict` | 用户想办理流程时推送流程链接（`{processes}` 动态注入） | 保持默认（勿删占位符） |
| 个性化提示词 `smart.prompt.profile` | 注入用户属性（`{profile_fields}`），仅判断个人资格，不主动透露身份 | 保持默认 |
| 风险提醒提示词 `smart.prompt.risk` | 回答涉及禁止/强制条款 → 追加「⚠️ 风险提示」（依据+后果+正确做法） | 企业合规要求强时保留/强化 |

### 8.6 智能模式：检索

> 界面位置：智能模式 Tab → 「检索」分区

| 配置项 | 默认 | 说明 |
|---|---|---|

## 9. 业务路由配置

> 入口：系统配置 → 「问答路由」（/console/config/routes）。四个 Tab：主题分类 / 动作意图 / 流程字典 / 对接人路由。
> **作用**：让 AI"从回答走到行动"——识别出用户想办事 → 推流程链接；识别出用户要找人 → 推对接人。

### 9.1 主题分类（policy_topics）

| 字段 | 说明 | 配置建议 |
|---|---|---|
| 名称/英文名 | 展示名称 | 与员工语言习惯一致 |
| 关键词 | 同义词（假期：休假/年假/婚假/产假/病假/请假） | **覆盖企业常用说法**，决定意图识别的召回 |
| 范围说明 | 涵盖什么/不含什么 | **注入意图识别提示词**，写清楚可大幅减少误归类 |

出厂 6 个主题（假期/考勤/出差/报销/外派/其他）。**企业特殊业务**（如"加班审批"归属考勤）可通过修改关键词和范围说明让 AI 归类更准。

### 9.2 流程字典（processes）

| 字段 | 说明 |
|---|---|
| 名称/英文名 | 展示（如"请假"） |
| URL | 流程申请链接（OA/飞书深链等） |
| 关联主题 | 兜底（无精确 flow 时按主题推） |
| 关键词 | 辅助匹配 |

**生效机制**：员工意图=办理流程（"我要请假"）→ AI 匹配流程 → 回答末尾推送**流程链接卡片**；查询类意图（"年假几天"）若有对应流程，末尾附弱提示"是否需要申请？"。

### 9.3 对接人路由（topic_routes）

| 字段 | 说明 |
|---|---|
| 主题 | 业务主题 |
| 地区 | 可选——**地区级对接人优先**，无地区配置用主题级兜底 |
| 对接人 | 从用户表选择（联系方式自动带出） |

**生效机制**：员工明确转人工（回复"转人工"/"找人工"等）→ 按"主题+员工地区"匹配对接人 → 推联系人卡片。

**配置示例**：假期主题 → 地区=广东 → 对接人=李婷（HRBP）；无地区 → 主题级兜底对接人。

## 10. 安全设置

> 入口：系统配置 → 「安全设置」（/console/config/security）。四个功能块：密级档位 / 密级策略矩阵 / 阅读保护 / 登录安全 / 审计日志。

### 10.1 密级档位 `security.levels`

- 出厂 4 档：公开 / 内部 / 机密 / 绝密（可增改档位，含中英文名）
- 政策文件必须选择密级（第 5.5 节）

### 10.2 密级策略矩阵 `security.policy`（核心安全机制）

每档密级可独立配置 4 个开关（UI 策略矩阵列）：

| 开关 | 作用 | 典型配置 |
|---|---|---|
| 浏览水印（Browse watermark） | 阅读页平铺用户姓名+工号+时间（截图溯源） | 机密+开 |
| 禁止复制（Copy protection） | 正文禁止选中/复制 | 内部+开 |
| **AI 可检索（AI searchable）** | 否=人可读、**AI 不引用**（硬过滤） | 机密+关（防止 AI 泄露） |
| 浏览审计（Browse audit） | 记录谁读了该密级文档 | 机密+开 |

> 注：**未授权访问尝试（403）总是记录**（无开关）——有人试图访问无权政策即安全事件，与目标密级无关。

**出厂默认策略**：公开（无保护，AI 可检索）/ 内部（禁复制，AI 可检索）/ 机密（水印+禁复制+AI 不可检索+审计）/ 绝密（同机密+审计）。

> **给管理员的建议**：高密级政策（人事、薪酬、审计）务必配置 `AI 可检索=否`——员工问相关问题时，AI 不会引用这些内容（防止敏感信息经 AI 外泄）。

### 10.3 阅读保护（全局开关）

| 开关 | 默认 | 说明 |
|---|---|---|
| 阅读页水印 `common.security.watermark_enabled` | 开 | 全局水印开关（密级策略可单独覆盖） |
| 阅读页禁止复制 `common.security.copy_protect_enabled` | 开 | 全局禁复制开关 |

### 10.4 登录安全

| 开关 | 默认 | 说明 |
|---|---|---|
| 首次登录强制改密 `common.security.force_change_on_first_login` | 关 | 用户须改密后才能使用（新建/导入/重置的用户均触发）。**生产建议开启** |

### 10.5 审计日志查看

- 安全设置页可浏览审计日志（chat/audit），按日查看
- 完整日志文件在 `data/logs/`（详见 11.2）

### 11.1 统计报表（入口：顶部导航「统计报表」/stats）

## 12. 备份与恢复

### 12.1 自动备份

```bash
node scripts/backup.mjs                          # 手动备份（默认保留最近 14 份）
BACKUP_DIR=D:/backup node scripts/backup.mjs      # 备份到异盘/网络盘（生产建议）
node scripts/backup.mjs --keep 30                 # 保留 30 份
```

- 备份内容：SQLite 主库（在线热备份，不阻塞写入）+ 向量库 + 上传文件 + 智能会话记忆
- 备份后自动校验 SQLite 可读
- **生产建议**：`register-schedules.ps1` 已注册每日 03:00 自动备份；备份目录建议指向异盘/网络盘（与数据不同盘）

### 12.2 恢复

```bash
node scripts/restore.mjs data/backup/2026-08-13_21-48-29            # 预览+确认（服务运行中会拒绝）
node scripts/restore.mjs data/backup/2026-08-13_21-48-29 --yes      # 跳过确认
node scripts/restore.mjs data/backup/2026-08-13_21-48-29 --stop     # 自动停服务后还原（需管理员）
```

**fail-safe 设计**：还原前自动把"当前数据"备份到 `data/backup/_pre-restore-<时间戳>/`（可反悔）；还原后校验 SQLite 可读；双存储一致性由后端启动时自动同步。

## 13. 监控与故障排查

### 13.1 探活与监控体系（register-schedules.ps1 已注册定时任务）

| 工具 | 频率 | 职责 | 告警方式 |
|---|---|---|---|
| `health-check.mjs` | 每 1 分钟 | 快故障：backend/python 存活与假死；连续 N 次失败 → 有 NSSM 服务则自动 restart，无服务则人工告警 | `data/logs/alerts/` + 可选 webhook |
| `monitor.mjs` | 每 5 分钟 | 慢变量：磁盘（阈值 80%）/内存（90%）/服务状态；**状态变化才告警**（防刷屏） | 同上 |
| 备份任务 | 每日 03:00 | 全量备份 | 失败告警 |

- 自定义阈值：`DISK_THRESHOLD` / `MEM_THRESHOLD` / `FAIL_THRESHOLD` 环境变量
- 接入企业告警：`MONITOR_WEBHOOK` 环境变量（告警 POST JSON 到企业 IM/邮件网关）

### 13.2 常见问题速查表（症状 → 诊断 → 处理）

| 症状 | 可能原因 | 处理步骤 |
|---|---|---|
| **问答全部拒答"未找到相关内容"** | ① 政策未发布/未到生效日期 ② 政策库被停用 ③ 模型未配置 ④ Python 未启动 | ① 政策管理检查版本状态 ② 库状态 ③ 模型接入页看 AI 指示灯 ④ `curl localhost:8001/health` |
| **检索时好时坏** | ① 多个 backend 实例抢端口 ② Python 内存索引异常 | ① `netstat -ano \| grep 3000` 确认只有一个监听，多实例全部杀掉 ② 重启 Python（BM25 自动重建） |
| **某员工看不到某政策** | 可见范围规则未匹配 | 检查该用户属性（部门/地区）与政策可见条件是否匹配（6.3）；临时可先放宽规则验证 |
| **AI 回答引用了不该用的政策（跨地区）** | 适用范围未配置 | 为该政策配置适用范围（6.4/8.2 适用性权重） |
| **本地模型回答慢/卡** | 本地模型本身慢 | 本地 9B 每轮 2-5s、agent 多轮首字 30-90s 属正常；确认显存足够（nvidia-smi）；考虑换云端模式 |
| **登录后看不到任何政策** | 可见范围 + 用户属性不匹配 | 6.3 排查；密级 ai_searchable=false 政策 AI 不引用（人可读） |
| **服务自动重启循环** | 生产构建问题 | 看 `data/logs/alerts/` 与 NSSM 日志；确认 `npm run build` 产物完整（`dist/` 含 main.js） |
| **前端白屏** | 开发模式 Vite 缓存 | 重启 vite dev server；生产确认构建产物/静态托管正常 |
| **HTTPS 证书告警** | 自签证书 | 属预期（客户端信任一次）；生产换正式证书 |

## 14. 安全加固清单

**必须项（生产上线前逐项确认）：**

- [ ] 配置可见范围（员工只能看到应看的政策）

**推荐项：**

- [ ] `BIND_HOST=0.0.0.0` 仅在需要局域网访问时设置（默认 127.0.0.1 不外露）
- [ ] 配置 `CORS_ORIGINS` 白名单（生产跨域收紧）
- [ ] 备份到异盘/网络盘（`BACKUP_DIR`）

- [ ] 审计日志定期归档（合规）

**安全设计说明**（管理员应了解的能力边界）：
- API Key 密文落盘（AES-256-GCM），明文永不落库
- 密码 scrypt 加盐哈希存储
- 会话 token 7 天有效期、登出吊销
- 权限防探测：无权内容"装不存在"（检索/直连均不可达）
- 前端防外泄 = 水印溯源 + 禁复制（**提高成本，不承诺杜绝**——DevTools/OCR/拍照仍可绕过）
